# 4.1. Programas interactivos

En la UT3 escribíamos los valores directamente en el código. Ahora queremos que **el usuario pueda proporcionar los datos mientras el programa se ejecuta**, sin modificar el archivo `.java`.

Un **programa interactivo** intercambia información con quien lo utiliza: puede mostrar preguntas o instrucciones, recibir datos y presentar resultados.

## 1️⃣ Programas con datos fijos y programas interactivos

Observa este programa, que calcula el coste de dos entradas:

```java
public class EntradasFijas {
    public static void main(String[] args) {
        double precio = 18.50;
        int cantidad = 2;
        double total = precio * cantidad;

        System.out.println("Total: " + total + " euros");
    }
}
```

**Salida:**

```text
Total: 37.0 euros
```

Si queremos calcular el coste de tres entradas, tenemos que cambiar el valor de `cantidad` en el código.

En un programa interactivo, en cambio, podríamos preguntar al usuario cuántas entradas desea comprar. El programa utilizaría la respuesta para calcular el total. **El cálculo no cambia; cambia de dónde proceden los datos.**

:::info[Lo importante]

Un programa interactivo no necesita tener ventanas ni botones. Un programa de consola que hace preguntas y recibe respuestas por teclado también es interactivo.

:::

## 2️⃣ El esquema entrada → proceso → salida

Recordamos un esquema que ya estudiamos en la UT1:

| Fase | ¿Qué ocurre? | Ejemplo: compra de entradas |
| --- | --- | --- |
| **Entrada** | El programa recibe los datos necesarios. | Precio: 18,50 €; cantidad: 3. |
| **Proceso** | El programa realiza operaciones con esos datos. | `18.50 * 3` |
| **Salida** | El programa comunica el resultado. | Total: 55,50 €. |

Este esquema nos ayuda a organizar cualquier ejercicio **antes de empezar a programar**.

### 🟩 Entrada

Los datos pueden proceder del teclado. En Java utilizaremos la clase `Scanner`, que estudiaremos en el apartado 4.2.

### 🟧 Proceso

Guardamos los datos en variables y aplicamos las operaciones que ya conocemos: suma, resta, multiplicación, división, etc.

### 🟥 Salida

Mostramos información mediante `System.out.print()` o `System.out.println()`.

:::tip[Antes de escribir código]

Pregúntate siempre: **¿qué datos necesito?, ¿qué debo calcular? y ¿qué resultado tengo que mostrar?**

:::

## 3️⃣ Primer ejemplo de interacción

Este ejemplo permite introducir la cantidad de entradas por teclado. No es necesario memorizar todavía las instrucciones de `Scanner`: las aprenderemos paso a paso en el siguiente apartado.

```java
import java.util.Scanner;

public class CompraEntradas {
    public static void main(String[] args) {
        Scanner teclado = new Scanner(System.in);

        double precio = 18.50;

        System.out.print("¿Cuántas entradas quieres comprar? ");
        int cantidad = teclado.nextInt();

        double total = precio * cantidad;

        System.out.println("Total: " + total + " euros");

        teclado.close();
    }
}
```

**Ejemplo de ejecución:**

```text
¿Cuántas entradas quieres comprar? 3
Total: 55.5 euros
```

El número `3` lo escribe el usuario. Si ejecutamos otra vez el programa y escribimos `2`, el total será `37.0 euros`, sin cambiar el código.

Fíjate en tres instrucciones:

- `System.out.print(...)` muestra una pregunta sin pasar automáticamente a la línea siguiente.
- `teclado.nextInt()` espera a que introduzcamos un número entero.
- `System.out.println(...)` muestra el resultado.

:::info[Sobre los decimales]

En el código Java escribimos los decimales con punto (`18.50`). En la salida del ejemplo aparece `55.5` porque todavía no hemos aplicado ningún formato para mostrar dos decimales.

:::

## 4️⃣ ¿Por qué son útiles los programas interactivos?

Imagina una pequeña aplicación para un taller de reparación de ordenadores. Cada cliente puede necesitar piezas diferentes y distintas horas de trabajo.

Si los precios estuvieran escritos en el código, habría que modificar el programa para cada reparación. Si el programa solicita los datos al usuario, podemos **reutilizarlo para muchos presupuestos**.

Otros ejemplos cercanos son calcular el coste de un viaje, la cuota de un gimnasio o el espacio de almacenamiento necesario para guardar archivos.

## 5️⃣ Buenas prácticas desde el principio

- **Preguntar con claridad:** indicar qué dato debe introducir el usuario y, cuando proceda, su unidad (euros, kilómetros, horas…).
- **Utilizar nombres descriptivos:** `precioEntrada` resulta más comprensible que `p`.
- **Separar las fases:** primero obtener los datos, después calcular y finalmente mostrar el resultado.
- **Probar diferentes valores:** no basta con que el programa funcione una sola vez.
- **Comprobar los resultados:** calcular mentalmente o con una calculadora algún caso sencillo.

:::warning[Una limitación por ahora]

En esta unidad aprenderemos a leer datos y a reconocer entradas incorrectas, pero todavía no sabemos programar decisiones para rechazarlas ni repetir preguntas automáticamente. Eso llegará en las UT5 y UT6.

:::
