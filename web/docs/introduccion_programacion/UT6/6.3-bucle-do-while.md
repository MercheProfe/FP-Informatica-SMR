# 6.3. El bucle do-while

## 1️⃣ Cuando la primera acción es obligatoria

Para elegir en un menú, primero hay que verlo y escribir una opción. Solo después podemos decidir si debemos repetirlo. `do-while` se ajusta a esa secuencia porque ejecuta el cuerpo **al menos una vez**.

También sirve para validar un dato: primero lo pedimos; después comprobamos si debemos volver a pedirlo. La condición indica cuándo **repetir**, por lo que suele expresar que el dato todavía es incorrecto.

## 2️⃣ Sintaxis y diferencia con while

Esquema de la estructura:

```text
do {
    instrucciones que se repiten
} while (condición);
```

1. Se ejecuta el cuerpo.
2. Se evalúa la condición.
3. Si es verdadera, se vuelve al principio del cuerpo.
4. Si es falsa, se continúa después del bucle.

:::warning[El punto y coma final sí es obligatorio]

`do-while` termina con `;` después del paréntesis de su condición. Esta regla es diferente de la del `while` con bloque estudiado en el apartado anterior.

:::

| Aspecto | while | do-while |
| --- | --- | --- |
| Comprueba la condición | Antes del cuerpo | Después del cuerpo |
| Mínimo de ejecuciones | Cero | Una |
| Primera lectura | Puede estar antes del bucle | Puede estar dentro del cuerpo |
| Uso habitual | Procesar mientras quede un dato pendiente | Pedir un dato o mostrar un menú antes de decidir |

## 3️⃣ Actividad guiada resuelta: menú de consulta

**Problema.** Mostrar un menú con dos consultas informativas y una salida. Tras cada consulta o entrada fuera del intervalo, volver a mostrarlo. La opción 0 finaliza. Las consultas muestran datos simulados.

Guarda el programa como `MenuConsulta.java`.

```java
import java.util.Scanner;

public class MenuConsulta {
    public static void main(String[] args) {
        Scanner teclado = new Scanner(System.in);
        int opcion;

        do {
            System.out.println("1. Consultar horario del taller");
            System.out.println("2. Consultar puestos disponibles");
            System.out.println("0. Salir");
            System.out.print("Opción: ");
            opcion = teclado.nextInt();

            switch (opcion) {
                case 1:
                    System.out.println("Horario simulado: de 9 a 14");
                    break;
                case 2:
                    System.out.println("Hay 4 puestos disponibles");
                    break;
                case 0:
                    System.out.println("Consulta terminada");
                    break;
                default:
                    System.out.println("Opción no válida");
            }
        } while (opcion != 0);

        teclado.close();
    }
}
```

### 🟩 Explicación paso a paso

Se declara `opcion` antes del bucle porque también se utiliza en su condición. Recibe un valor dentro del cuerpo, antes de llegar a esa condición.

El cuerpo muestra el menú, lee la elección y usa el `switch` conocido de la UT5. Después se comprueba `opcion != 0`. Tanto las consultas como las opciones incorrectas mantienen el menú activo; la opción 0 hace falsa la condición.

Los `break` del `switch` terminan el caso seleccionado y salen del `switch`. **No terminan el `do-while`**: este decide si continúa al evaluar su condición.

### 🟦 Comprobación de una sesión

| Entrada | Respuesta | ¿Se repite el menú? |
| --- | --- | --- |
| 2 | Hay 4 puestos disponibles | Sí |
| 7 | Opción no válida | Sí |
| 1 | Horario simulado: de 9 a 14 | Sí |
| 0 | Consulta terminada | No |

Si la primera elección es 0, el cuerpo se ejecuta una vez: el menú se muestra y el programa termina tras la despedida.

## 4️⃣ Aplicarlo a la validación

Para admitir un porcentaje de batería entre 0 y 100, ambos incluidos, debemos repetir la petición cuando `porcentaje < 0 || porcentaje > 100`. Basta con estar por debajo **o** por encima para que sea incorrecto. Usar `&&` exigiría estar simultáneamente por debajo de 0 y por encima de 100, algo imposible.

La petición y la lectura se colocan en el cuerpo. Un aviso mediante `if` puede explicar que el valor queda fuera del intervalo. Al terminar, sabemos que el porcentaje está dentro del rango.

:::info[Validar el rango no equivale a validar el tipo]

En los ejemplos y actividades con lecturas numéricas se presupone que se escribe un número del tipo solicitado. `nextInt()` no convierte una palabra en un entero: introducir letras provoca un error de lectura. Aquí se trabaja la repetición y la validación de rangos; el tratamiento de entradas de tipo incorrecto queda fuera de estos ejemplos.

:::
