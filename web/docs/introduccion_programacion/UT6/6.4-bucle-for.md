# 6.4. El bucle for

## 1️⃣ Un recorrido conocido

Un técnico quiere generar las etiquetas de los puestos del 1 al 5. Conoce el primer número, el último y cómo avanzar. `for` permite reunir esos tres elementos en una cabecera.

Es habitual cuando podemos describir el recorrido desde el principio. No significa que los límites deban ser constantes: también pueden proceder de un dato leído con `Scanner`.

## 2️⃣ Las tres partes de la cabecera

Esquema de la estructura:

```text
for (inicialización; condición; actualización) {
    instrucciones que se repiten
}
```

| Parte | Cuándo se ejecuta | Para qué sirve |
| --- | --- | --- |
| Inicialización | Una vez, al comenzar | Preparar la variable del recorrido |
| Condición | Antes de cada posible vuelta | Decidir si se ejecuta el cuerpo |
| Actualización | Después del cuerpo de cada vuelta | Avanzar al siguiente valor |

El orden es **inicialización → condición → cuerpo → actualización → condición…**. Cuando la condición es falsa, se sale. Puede haber cero iteraciones.

Los dos puntos y coma separan las partes de la cabecera; no son puntos y coma añadidos después de `for`. Si se declara la variable en la inicialización, solo puede utilizarse dentro del `for`, incluida su cabecera.

## 3️⃣ Actividad guiada resuelta: etiquetas de puestos

**Problema.** Pedir el número de puestos de un aula. Si es positivo, mostrar las etiquetas desde el puesto 1 hasta el último. Si no es positivo, mostrar un aviso y no generar etiquetas.

Guarda el programa como `EtiquetasPuestos.java`.

```java
import java.util.Scanner;

public class EtiquetasPuestos {
    public static void main(String[] args) {
        Scanner teclado = new Scanner(System.in);

        System.out.print("Número de puestos: ");
        int cantidad = teclado.nextInt();

        if (cantidad <= 0) {
            System.out.println("La cantidad debe ser positiva");
        } else {
            for (int puesto = 1; puesto <= cantidad; puesto++) {
                System.out.println("Etiqueta: Puesto " + puesto);
            }
        }

        teclado.close();
    }
}
```

### 🟩 Explicación y traza

El `if` separa el caso incorrecto. Para una cantidad positiva, `puesto` empieza en 1 y avanza una unidad después de cada etiqueta. La condición incluye el último puesto porque utiliza `<=`.

Con una entrada de 3:

| Momento | Valor de puesto | Resultado |
| --- | --- | --- |
| Inicialización y primera condición | 1 | Muestra Etiqueta: Puesto 1 |
| Actualización y segunda condición | 2 | Muestra Etiqueta: Puesto 2 |
| Actualización y tercera condición | 3 | Muestra Etiqueta: Puesto 3 |
| Actualización y cuarta condición | 4 | La condición es falsa; termina |

La inicialización ocurre una vez; el cuerpo y la actualización, tres; la condición, cuatro. Con una cantidad de 1 se genera una etiqueta. Con 0 se muestra el aviso.

## 4️⃣ Recorridos ascendentes y descendentes

Un recorrido debe hacer compatibles el inicio, el límite y el cambio. Estas son cabeceras de referencia, no programas completos:

| Recorrido | Cabecera | Valores que toma i en el cuerpo |
| --- | --- | --- |
| Ascendente | `for (int i = 1; i <= 4; i++)` | 1, 2, 3, 4 |
| Descendente | `for (int i = 4; i >= 1; i--)` | 4, 3, 2, 1 |
| De dos en dos | `for (int i = 2; i <= 8; i += 2)` | 2, 4, 6, 8 |
| Límite excluido | `for (int i = 1; i < 4; i++)` | 1, 2, 3 |

`i += 2` suma dos al valor anterior. Una actualización no tiene que ser siempre de una unidad.

:::warning[Un único lugar para avanzar]

Si la cabecera ya incrementa la variable, no la incrementes otra vez dentro del cuerpo sin una razón clara: podrías saltarte valores. En un descenso, una actualización ascendente puede impedir que el recorrido termine.

:::

## 5️⃣ Comparación con while

El recorrido de las etiquetas también puede expresarse con `while`: preparar `puesto` antes, comprobar el mismo límite y actualizarlo al final del cuerpo. Si se conservan esos pasos en el mismo orden, el resultado será el mismo.

`for` reúne el control de un recorrido en una línea. `while` suele resultar más claro cuando la repetición depende de una nueva respuesta o de un dato de finalización. Elige la estructura que permita entender mejor cuándo se empieza, cuándo se continúa y cómo se termina.
