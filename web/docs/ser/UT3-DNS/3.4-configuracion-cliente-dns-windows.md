# Configuración del cliente DNS en Windows

En los apartados anteriores hemos estudiado cómo funciona DNS y qué información almacenan sus servidores. Ahora veremos **cómo sabe un equipo Windows a qué servidor DNS debe consultar**, cómo modificar esa configuración y cómo comprobarla.

**RA relacionado:** RA2. **CE principales:** b), h) (preparación para la comprobación del servicio).  
**Entorno:** `SER-Cliente` (Windows) y, cuando esté disponible, `SER-Servidor` (Windows Server). **No instalaremos todavía el rol DNS.**

## 1️⃣ ¿Qué necesita un cliente para resolver nombres?

Para resolver un nombre mediante DNS, un cliente debe conocer al menos la dirección IP de un **servidor DNS** al que enviar la consulta. Esa dirección puede configurarse manualmente o recibirse por DHCP.

| Elemento | Función | Ejemplo ilustrativo |
|---|---|---|
| Dirección IP del cliente | Identifica el equipo en la red | `192.168.10.100` |
| Máscara o prefijo | Delimita la red local | `/24` |
| Puerta de enlace | Permite alcanzar otras redes | `192.168.10.1` |
| Servidor DNS | Responde o tramita consultas de nombres | `192.168.10.10` |
| Sufijo DNS | Facilita la búsqueda de nombres no completos | `empresa.test` |

:::info[No confundas puerta de enlace y servidor DNS]
La puerta de enlace encamina paquetes hacia otras redes; el DNS resuelve nombres. Pueden coincidir en un mismo dispositivo, pero **son funciones distintas**. Un equipo puede tener conectividad por IP y, aun así, fallar al resolver nombres.
:::

Los valores de la tabla son **ejemplos**. En las prácticas utilizaremos la configuración real de nuestras máquinas virtuales.

## 2️⃣ Configuración automática mediante DHCP

En la UT1 estudiamos cómo DHCP entrega parámetros de red a un cliente. Entre ellos puede incluir los necesarios para DNS:

| Opción DHCP | Qué proporciona |
|---|---|
| **006 — DNS Servers** | Una o varias direcciones de servidores DNS |
| **015 — DNS Domain Name** | Un nombre de dominio que Windows puede utilizar como sufijo DNS |

Cuando el cliente recibe una concesión DHCP, puede utilizar los servidores DNS anunciados sin introducirlos manualmente.

**Ejemplo:** si el servidor DHCP entrega la IP `192.168.10.100`, una máscara `/24`, la puerta de enlace `192.168.10.1` y DNS `192.168.10.10`, el cliente enviará normalmente sus consultas DNS a `192.168.10.10`.

:::warning[Precaución en nuestro laboratorio]
En la red interna de VirtualBox no debemos suponer que existe salida a Internet ni que ya tenemos un servidor DNS operativo. **Recibir la IP de un DNS por DHCP no garantiza que ese servidor esté instalado, tenga la zona configurada o pueda resolver nombres externos.**
:::

## 3️⃣ Configuración manual del DNS en Windows

Podemos mantener la dirección IP obtenida por DHCP y cambiar **solo el servidor DNS**. Es útil cuando queremos que un cliente consulte un servidor concreto para realizar pruebas.

En Windows 10/11, una ruta habitual es:

1. Abre **Configuración → Red e Internet**.
2. Selecciona el adaptador correspondiente a la **red del laboratorio**.
3. Busca la opción **Asignación del servidor DNS** y pulsa **Editar**. Según la versión de Windows, también puedes abrir las propiedades del adaptador desde **Conexiones de red**, seleccionar **Protocolo de Internet versión 4 (TCP/IPv4)** y entrar en **Propiedades**.
4. Elige la configuración manual de DNS para IPv4 e introduce la dirección indicada por el profesor.
5. Guarda los cambios y verifica el resultado con `ipconfig /all`.

:::warning[No inventes la IP del servidor]
No introduzcas `192.168.10.10` por el mero hecho de que aparezca en nuestros ejemplos. Utiliza **la IP real de `SER-Servidor`**, y solo cuando hayamos comprobado que presta el servicio DNS. Si todavía no está instalado, anota el procedimiento sin alterar la configuración que funciona.
:::

**Servidor DNS preferido y alternativo:** Windows permite configurar más de un servidor. El alternativo **no es una copia automática de las zonas**: debe ser otro DNS capaz de responder correctamente. Más adelante utilizaremos Windows Server y Ubuntu/BIND9 para estudiar esta situación.

## 4️⃣ Consultas DNS con `nslookup`

`nslookup` es una herramienta de consulta DNS. Permite preguntar a un servidor concreto por un nombre o un registro.

```powershell
nslookup www.example.com
```

La salida muestra el servidor DNS utilizado y la información que este devuelve, si puede resolver la consulta.

También podemos indicar explícitamente un servidor DNS:

```powershell
nslookup www.example.com 1.1.1.1
```

Este segundo comando **solo funcionará si existe conectividad con ese servidor externo**. No lo utilizaremos como prueba obligatoria dentro de una red interna aislada.

Para consultar un tipo de registro:

```powershell
nslookup -type=A www.example.com
nslookup -type=MX example.com
nslookup -type=NS example.com
```

Cuando instalemos nuestro DNS interno, sustituiremos los nombres y direcciones de ejemplo por los de la zona del laboratorio.

:::tip[¿Por qué `ping` y `nslookup` pueden dar resultados distintos?]
`ping` utiliza la resolución de nombres del sistema, que puede considerar el archivo `hosts` y otros mecanismos. `nslookup` consulta DNS directamente y **no utiliza el archivo `hosts` para resolver el nombre solicitado**. Ya lo comprobamos en la práctica P01.
:::

### 🟥 Actividad 3. Interpreta los comandos

Explica qué información solicita cada instrucción y qué servidor DNS se utiliza:

```powershell

nslookup -type=MX empresa.test

```

## 5️⃣ Caché DNS del cliente

Windows puede almacenar respuestas DNS temporalmente. Esto reduce consultas repetidas, pero puede provocar que un cambio reciente todavía no se refleje en el cliente.

Para examinar la caché DNS del sistema:

```powershell
ipconfig /displaydns
```

Para vaciarla:

```powershell
ipconfig /flushdns
```

Vaciar la caché **no modifica los registros del servidor DNS**, no corrige una zona mal configurada y no garantiza que un nombre vaya a resolverse.

## 6️⃣ Cómo distinguir un fallo DNS de un fallo de red

Cuando un nombre no funciona, conviene comprobar primero si existe conectividad IP y después investigar la resolución.

| Comprobación | Herramienta | Qué permite averiguar |
|---|---|---|
| Configuración del adaptador | `ipconfig /all` | IP, máscara, DHCP y DNS configurados |
| Conectividad con una IP conocida | `ping <IP>` | Si existe respuesta ICMP del destino; su bloqueo no demuestra falta de conectividad |
| Consulta de un nombre | `nslookup <nombre>` | Si el servidor DNS responde a la consulta |
| Consulta a un DNS específico | `nslookup <nombre> <IP_DNS>` | Si ese servidor concreto responde |
| Caché del cliente | `ipconfig /displaydns` | Respuestas almacenadas localmente |

**Ejemplo de diagnóstico:**

- El cliente puede comunicarse con `192.168.10.20` por IP.
- No consigue resolver `web.empresa.test`.
- `ipconfig /all` muestra como DNS una dirección que no corresponde al servidor configurado.

La conectividad IP parece funcionar, pero debemos **revisar la configuración DNS del cliente**. No sería razonable empezar cambiando la máscara o la puerta de enlace sin más comprobaciones.

### 🟦 Actividad 5. Diagnóstico razonado

En cada caso, indica **qué comprobarías primero** y qué herramienta utilizarías:

1. Un cliente puede acceder a un servidor por IP, pero no por su nombre.
2. `ipconfig /all` muestra una dirección DNS que no corresponde a la red del laboratorio.
3. Un cliente resuelve un nombre a una IP antigua después de cambiar el registro.
4. `nslookup` devuelve una IP, pero la página web no carga.
5. `nslookup` no obtiene respuesta y tampoco hay conectividad con la IP del servidor DNS.

## 8️⃣ Resumen

- Un cliente necesita conocer la dirección de un servidor DNS para realizar consultas a través de él.
- La dirección DNS puede configurarse manualmente o recibirse por DHCP (opción 006).
- El sufijo DNS puede recibirse mediante DHCP (opción 015).
- `ipconfig /all` muestra la configuración; `nslookup` permite consultar DNS.
- La caché puede conservar respuestas hasta que expire su TTL; `ipconfig /flushdns` vacía la caché local.
- **Resolver un nombre y alcanzar un servicio son comprobaciones diferentes.**
